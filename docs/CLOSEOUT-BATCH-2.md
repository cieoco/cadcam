## 證據與修正

- B2-1：1280×720 時 SVG 畫布 x=188..960、y=57..720；從動齒輪輪廓 x≈387..1077、y≈43..734，超出右／上／下界。`currentBounds()` 只納入求解接點，漏掉齒頂圓。
- 局部修正：只在現有 fit 外接框補入齒輪外緣，齒數與節圓半徑採相同繪製規則，不改求解或機件資料。

### 2D／3D 裁切

- `app.js/currentBounds()`：補入每個齒輪的齒頂圓，而非只看軸心／輸出孔。
- 修正後桌機 1280×720：從動輪外框 x≈483..934、y≈163..614，位於畫布 x=188..960、y=57..720 內；量測的齒輪與機架 polygon 均 `clipped: false`。
- 390×844 手機版，從「專案 → 開啟 → 範例 → 齒輪對」載入，截圖確認兩顆齒輪完整可見。
- 360×640：畫布 x=0..360、y=44..530；從動輪外框 x≈138..348、y≈182..392；三個 polygon 皆未超界。手機「置中」也實際操作。
- 手機 3D 原本仍裁兩側；原因是初始相機距離未補償直向寬高比。`viewer.js` 的初始距離除以 `min(1, camera.aspect)`，維持橫向距離不變。390×844 初次開啟 3D 重驗，兩顆齒輪完整可見，能返回 2D。不重設使用者後續旋轉／縮放。

### 拖曳吸附與手機面板跳動

桌機先以 UI 新增地錨與 128 mm 自由桿，保存起始作品，再把桿端拖到地錨：

- 狀態由 DOF 3「太鬆」變 DOF 1「請加動力」；「分離」按鈕出現。
- 按復原後回 DOF 3。手勢程式修正後再重跑一次，仍通過。
- 真實下載的 `blocks (7).json`（起始）、`blocks (8).json`（接合）、`blocks (9).json`（復原）與 `blocks (10).json`（手機接合）均為 2 元件、桿長 128 mm。
- 起始／復原：地錨 id=A1，桿端 id=P2a/P2b；接合後：桿端 id=A1/P2b。確認是資料上的合併，非視覺重疊。

手機首次操作發現實際缺陷：從「建構」按下接點就切換「編輯」，零件盤消失使 SVG 高度變大，地錨在拖曳途中移位。原流程第一次拖曳落空，面板已展開後第二次才接合。

`input.js` 局部修正：手機接點按下時記錄待開面板，pointerup 完成拖曳後才展開；pointercancel 或雙指接手則取消待開面板。重新載入修正後，390×844 從建構模式一次拖曳即合併成功，之後正常顯示角色面板。桌機接點選取仍立即開啟面板。

### 雙指事件程式驗證

新增 `test/input-gestures.mjs`，以假的 SVG 與 requestAnimationFrame 佇列重現 capture／target／bubble 路由，直接測試真實 Input/View 模組。

修正前：背景 pinch 通過，但零件阻止冒泡、機架拖曳清理與最後手指放開路由共 3 項失敗。手機面板時機另有 1 項先重現失敗。

`input.js` 修正：

- 在 capture 階段記錄指標，避免零件 stopPropagation 使第二指消失。
- 第二指由縮放接手，阻止它啟動另一段零件操作；補上 pointer capture。
- 直到全部手指離開才恢復單指編輯，避免第一指離開後剩餘手指觸發移動／合併。
- 交接時清除待啟動接點、機架與畫桿拖曳狀態；已完成的單指位移保留一筆 undo。

## 限制與後續

目前瀏覽器操作 API 有單指／滑鼠 drag 與視窗尺寸調整，未列出可同時控制兩個觸點的操作；真實雙指手勢不可用滑鼠或單元測試冒充通過。

**仍未完成：真實手機雙指硬體驗收。** 請在 Android Chrome／iOS Safari 分別驗證：

1. 在背景及零件上各放下兩指，拉開／捏合／平移，畫布應縮放而機構資料不變。
2. 第一指先按接點（未拖動及已拖動各一次），第二指加入；不應突然移動接點或吸附到別處。
3. 先放開一指，再移動另一指，不應恢復拖曳；全部放開後，新的一指拖曳應恢復正常。
4. 重複上述流程於畫桿模式、pointercancel（例如系統中斷）與螢幕旋轉後。

程式回歸不涵蓋瀏覽器的真實 pointer capture／觸控分派與作業系統手勢，故 B2-4 不標成完整通過。也未宣稱已測全部機件、全部手機瀏覽器。
