# SDD — 操作一致性：零件 × 動作對照表與共用動作流程

日期：2026-11-11（Asia/Taipei）
狀態：使用者同意方向並要求以 LOOP 施工至完成（2026-11-11）。啟動大小上限：使用者 2026-11-11 同意由 2,165,000 放寬到 2,200,000 bytes（`test/startup-size.mjs`）；仍以按需載入為原則，再調高需使用者同意。

## 0. 一句話

問題不是某一個動作有 bug，而是每個動作各寫一套「試算、檢查、套用、復原、訊息」，選取也各自解讀。本 SDD 不重寫：先用一張「零件 × 動作」對照表把缺口一次列出，再把動作逐一搬到一條共用流程上，舊寫法跟著刪掉。

## 1. 根因（2026-11-11 盤點）

1. **動作各自一套流程。** 直接改寫 `S.comps` 的檔案 19 個、`pushUndo()` 80 處。規則修在一個入口，其他入口不會跟著對（例：刪除仍用舊的馬達座板檢查，被既有問題擋住不相干的刪除）。
2. **選取沒有統一答案。** `S.selectedNodeId／LinkId／TriangleId／SliderId／GearId／SprocketId` 六個欄位，各指令自行解讀。使用者想的是「這根桿」，程式記的是「桿上的孔」（例：選到孔時按 Delete 沒有反應也沒有提示）。
3. **關係藏在別的零件裡。** 馬達接輸出後資料記在桿件上，刪桿件等於刪馬達。接合一致性（C0–C7）只做到事後檢查。
4. **拖曳的意義由一長串判斷決定。** `input.js` 有 14 個模式旗標依序判斷，加一種行為就可能改到別的行為的優先順序。
5. **測試跟著功能寫。** 沒有測試走過「每種零件 × 每個動作」，缺口由使用者操作時才發現。

## 2. 目標與不做

- **目標：** 同一個動作對每種零件的行為可預期、可查表；每個動作都有回饋（做了什麼，或為什麼不能做）；規則只寫一次。
- **不做：** 不重寫求解器、不改存檔格式（馬達獨立化另寫規格，見 O5）、不新增模式切換、不改既有合法作品的結果。
- **沿用：** 接合關係索引 `relations.js`、一致性檢查 `integrity.js`、提交關卡 `integrity-gate.js`（只擋這次新造成的問題）、`describeIssue` 的學生用語。

## 3. 設計

### 3.1 零件 × 動作對照表（單一來源）

`js/blocks/operation-matrix.js`（純資料，按需載入；測試與文件共用）：

- 零件：桿件、板材、L型件、彎桿／多臂件、馬達（獨立與已接輸出）、齒輪、滑軌、針筒、機架孔。
- 動作：選取、移動、改尺寸、刪除、連接、解除、複製／鏡射。
- 每格：`expect`（學生看得到的結果一句話）、`when`（前提：未接／已接／接固定孔／接馬達）、`status`（`ok`／`gap`／`n/a`）。`gap` 必須附現況與預期。

### 3.2 共用動作流程

`js/blocks/edit-pipeline.js`（按需載入）：

```
runEdit({name, target, plan}) →
  plan(work) → {ok, comps, params, modules, follow?, message?}   // 純函式：只產生候選，不碰 S、不碰 DOM
  → 共用檢查：integrityGate(before, after)（只擋新問題）＋該動作宣告的檢查
  → 套用：pushUndo 一次、寫回 S、清理 topo 參照、rebuild/draw
  → 回饋：成功一句話或拒絕原因（describeIssue 用語）；沒有任何情況是「沒反應」
```

- 每個動作只寫 `plan`。套用、復原、訊息、既有問題的處理都在流程裡，只有一份。
- 「既有問題不擋不相干的修改」是流程的規則，不是各動作各自記得。
- 搬遷一個動作＝刪掉它舊的套用／復原／訊息程式碼；啟動路徑上的程式只減不增。

### 3.3 選取解讀

`js/blocks/selection-target.js`：`targetOf(S) → {part, hole?, joint?, shared: [parts]}`。

- 選到零件上的孔 → `part` 是孔所屬零件；選到多零件共用的接點 → `shared` 列出零件，由指令決定（刪除：不猜，請使用者點桿身；圖上高亮候選）。
- 指令一律問 `targetOf`，不再自己讀六個欄位。六個欄位先保留當儲存，逐步收斂。

### 3.4 拖曳意圖

`js/blocks/drag-intent.js`：`dragIntent(target, context) → 'drive'|'move-free'|'resize-handle'|'pan'|'draw'|…`，純函式＋對照測試；`input.js` 依結果分派。先把現有判斷順序原樣搬進表（行為不變），再逐格對照 3.1 修正。

## 4. 驗收

- 對照表測試：每格 `ok` 都有一個可重跑的檢查（Node，以真實域模組與假 DOM）；`gap` 列在報告，隨分包歸零。
- 每個搬遷的動作：同一物件用按鍵／按鈕／拖曳做同一件事結果相同；失敗有訊息；一次復原；保存重開；桌機與手機瀏覽器驗收。
- 既有全套 Node 測試通過；瀏覽器套件失敗清單不多於基準；啟動大小不超過現行上限。

## 6. 風險

- **搬遷中兩套並存：** 每包結束時，被搬的動作只剩一個入口；用 grep 檢查舊函式無呼叫者。
- **啟動大小：** 新模組按需載入；搬遷以刪除啟動路徑上的舊碼為主。若某包無法在上限內完成，停下回報，不自行調高上限。
- **行為改變：** 只有對照表標為 `gap` 的格子可以改行為；其餘以 parity 測試釘住。
