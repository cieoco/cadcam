# FTC 功能模組：快速原型＋數位樂高

## 最高指導原則：教學與應用，在同一件作品中完成

**讓使用者快速做出能探索的原型，在操作中理解機械原理，再把可修改、可重組的功能積木逐步轉為可製作的作品。**

以下原則優先於個別範例、功能清單及 UI 方案；既有 R1 實作只是一個起點，不代表已滿足全部原則。

- **快速原型：先得到可操作的結果。** 從「我要抓取／抬升／伸出什麼」進入，用少量必要資訊產生或調整原型；立即看見結果，不要求先理解所有 CAD 參數。
- **教學：看得懂因果，也保有決策。** 自動計算需讓使用者看見「改了什麼 → 哪裡改變 → 為什麼／限制是什麼」，能試不同方案、比較與復原。說明隨操作與選取出現，避免用常駐長文取代探索。
- **數位樂高：能拆、能改、能接、能重用。** 功能模組有明確的安裝、動力及輸出接口，並能展開為可編輯零件；範例不是只能播放的封閉模型。自動輔助不得抹掉手動改造，超出支援範圍時要保留作品並指出限制。
- **應用：與實際製作保持連結。** 尺寸、孔位、材料、硬體、加工及組裝資料逐步補齊，能保存與重現；清楚區分幾何預覽、加工就緒及實物驗證，不以動畫順暢代替可用性。
- **直覺操作：優先在作品上操作與回饋。** 物件、孔位、尺寸、運動及限制盡量在畫布上看見；數字欄位作為精確輸入的補充。教學與應用共用同一份作品，不以新增兩套介面或多層導覽來分流。

設計取捨：自動化優先省去重複計算，保留能幫助理解的選擇與可檢視的結果。新增功能必須具體改善「更快做出、理解因果、可重組、可落地」至少一項，且不能無理由損害其他項。

## 目標與邊界

剛性桿件共用操作與本輪實作邊界見 [SDD-RIGID-MEMBERS.md](SDD-RIGID-MEMBERS.md)；夾爪不是獨立編輯器，孔距與外形尺寸必須沿用該規則。

使用者先表達機械任務，再調整一個可動、可修改、可保存的原型，逐步完成真實零件選型與製作。不是把教學文字或更多面板加到通用 CAD 上。

功能族循序建立：夾取／釋放 → 升降／伸出 → 夾爪安裝到升降模組；之後才擴充滾輪收集及姿態保持。每族先完成一條小流程，不一次建立全部模板。

「幾何可動」「加工資料完整」「實物驗證」是三個不同狀態。現有示範馬達、齒輪與孔位不代表 FTC 合規或可直接製作；硬體選型、扭矩、限位、碰撞及年度規則需另行確認。

## R1：對稱雙齒輪夾爪

入口沿用既有夾爪範例。以原本教學卡的位置呈現任務操作，不新增頁面、浮動視窗、步驟導覽或常駐側欄。編輯零件時讓位給既有編輯面板。

1. 載入夾爪：沿用 GearA、GearB、LeftJaw、RightJaw，不重新生成使用者作品。
2. 輸入方形物件寬度（10–150 mm）及單側放入餘量（2–40 mm）；預設 50 / 10 mm。
3. 「張開」「閉合」立即顯示對應姿態；原有播放在兩者之間往返。淨距以既有板形的圓頭半徑估算，不能稱為碰撞模擬或夾持成功。
4. 同一卡片顯示預估淨開口與限制說明，可下載製作記錄。實際 DXF／SVG 沿用原有匯出功能。
5. 正常存檔／載入／分享／復原需保留任務參數。改尺寸不重建或覆蓋零件。

夾爪任務不重複顯示原有接點距離卡（接點是折彎處，不是爪尖）。手機畫布排在任務卡下方，編輯零件時隱藏任務卡並釋放畫布。置中包含張開／閉合兩姿態的實際爪尖範圍。

資料使用既有 snapshot 的 params：gripperWorkflow=1、gripperObjectWidth、gripperClearance。一般作品沒有 marker 就不啟用。舊版範例／檔案仍可自由操作，不遷移或偷偷啟用。

## 實作邊界

- gripper-workflow.js：純計算，重用 compileTopology / solveTopology；檢查原始對稱結構、嚙合中心距、有限解與單調閉合區間；回傳計畫或明確失敗原因。製作記錄列出尚未驗證事項及完整 snapshot。
- gripper-controller.js：表單、姿態切換、有限播放範圍、下載及現有卡片切換。透過依賴注入接 app；每次 rebuild 更新計畫，不每幀重新求解整段範圍。
- app.js：只做接線。既有 inputRockRange 優先採用有效夾爪計畫；無效工作流程阻止播放，不退回整圈旋轉。播放啟動與每步均不可超出範圍。
- examples.js：只在既有 gear-gripper 加入上述 params。HTML 修改限於原卡片內容及局部樣式。
- 不更動凍結的 mechanism 應用、不換框架、不新增依賴、不重構 solver、不宣稱完整碰撞或硬體設計完成。

## R1 驗收

- A1：50 mm 物件、10 mm 單側餘量得到閉合約 50 mm／張開約 70 mm；整段解有效、對稱且淨距單調。
- A2：張開／閉合與播放使用同一角度計畫；窄範圍也不能越界。
- A3：輸入不合法、不可達、結構不符時明確提示；不改動作品、不輸出成功記錄、不允許流程播放。
- A4：數值與 marker 經 snapshot 正規化、分享及復原保留；其他範例仍走原流程。
- A5：製作記錄包含任務數值、模型角度、幾何零件清單、snapshot、硬體與實物未驗證項，不暗示可直接加工裝配。
- A6：瀏覽器實際操作載入 → 調尺寸 → 開合 → 播放 → 下載；桌機／窄畫面可操作，無重疊的工作流程與零件編輯面板。

## 後續（尚未施工）

R1 收斂：修正中等視窗任務卡遮擋齒輪，查明 80 mm 新製作記錄的下載落地問題。不能用先前 50 mm 檔案當成這次下載成功的證據。

下一個教學／應用小循環：在畫布上呈現待抓物件，能直接修改尺寸，並看見物件寬度、放入餘量與夾爪姿態的對應；保留精確數值輸入與復原。物件示意不等於碰撞模擬；夾爪尚未依物件自動重設形狀，需明確說明。先定義這一小步的操作驗收，再派施工。

R2：確立軸、傳扭、軸承、馬達、板厚與加工公差，核對輸出，記錄實物回饋。

R3：升降模組及模組接口。先定義機架安裝面、動力輸入、工作輸出端，再實作夾爪接上升降；不以共用一個點 ID 冒充已完成硬體接口。

## R1b：看見物件、直接改尺寸（優先於 R1 的新版範例規則）

- 新載入的 gear-gripper 改成相向內彎爪端，沿用現有四個可編輯零件，不重建使用者存檔。舊外彎作品保留，任務規劃提示重新載入新版範例，不冒充可夾持的新版。
- 方形示意物件固定在閉合姿態的爪尖中心；播放時物件不跟著爪尖移動。兩側把手可拖曳改寬度，鍵盤左右鍵亦可調整；數值欄位是精確輸入的補充。
- 尺寸拖曳即時顯示預估開口及物件，放開後保存；一次拖曳僅一筆復原，取消則回復。拖曳不修改既有零件、不自動置中、不拖動整個機架。
- 畫布顯示當前爪尖淨距，以及「張開開口＝物件寬度＋兩側餘量」的對應。物件是參考，不參與 solver、零件清單或 DXF；明示非碰撞模擬。
- 超出可達開口時保留要求尺寸的示意與可調把手，說明需要縮小物件／餘量或改機構，禁止假裝成功播放。
- 卡片保持精簡；所有中窄視窗都為原卡片預留空間，不覆蓋齒輪。下載檔名含尺寸與時間，以新檔內容核對本次參數。

驗收：50→80 mm 畫布拖曳／精確輸入與一次復原；播放時物件固定、爪尖淨距更新；不可達尺寸可修回；手機可拖且無面板遮擋；同一次 80 mm 示範的新下載內容正確；舊資料保持未修改，其他範例不出現示意物件。
