# SDD — blocks 實作界面規劃

> 對象：`blocks.html` / `js/blocks/` 的使用者介面。  
> 目標：範例與 3D 呈現收斂後，開始把 blocks 做成可長期使用的「機構實作界面」；同時支援桌機、平板、手機。

---

## 1. 北極星

blocks 的第一畫面應該是「可以直接做機構」的工作台，不是展示頁。

使用者進來後只需要理解四件事：

1. **放零件**：地錨、桿件、滑軌、齒輪、動力來源。
2. **接起來**：拖點吸附、對孔、對齒、對滑軌。
3. **調零件**：長度、齒數、角色、行程、疊層。
4. **看結果**：播放、軌跡、警告、2D/3D。

UI 的責任是把這四件事分清楚，讓按鈕不再平鋪成一串。

---

## 2. 現況問題

目前 `blocks.html` 已具備可用雛形：

- 上方：復原、存檔、開啟、分享、範例、回機構工具。
- 左側/手機底部：零件盤。
- 畫布浮層：長度、接點、伺服、齒輪、滑塊、活塞等編輯面板。
- 底部浮列：播放、角度、置中、孔、鎖、3D、清空。

問題也開始明顯：

- **功能分類不清**：檔案、建構、播放、視圖、診斷混在不同角落。
- **手機空間緊**：底部零件盤、播放列、浮動面板容易互相擋住。
- **面板太浮**：選到不同物件時，面板位置與內容分散，未來零件更多會失控。
- **桌機和平板沒有分工**：桌機可承受左右欄；平板需要抽屜/底部 sheet；手機需要極簡底部導航。
- **按鈕缺少優先級**：高頻操作和低頻操作同樣可見，之後加凸輪/皮帶輪/齒條會更擠。

## 3. 按鈕分類

所有按鈕先分成五群。實作時每顆按鈕都必須歸群，不能隨手塞進工具列。

> **UI-1（2026-10-27）現況**：電腦與手機共用單一指令清單 `js/blocks/ui-commands.js`，分成「新增／調整／視圖／專案／說明」五類（與手機下方分頁同名）。電腦頂端只留身分（名稱＋作品名）、設計／組立、復原、「專案 ▾」「說明 ▾」；視圖指令（置中、3D、鎖孔距、尺規、量尺）在畫布工具列，手機在「視圖」分頁；卡榫盒子在「新增 → 外掛」；範例在「專案 → 範例…」。狀態訊息在畫布狀態列。播放列的快捷鍵（復原、置中、3D）兩種版面相同。新增按鈕時先把它歸進清單的某一類，由 `js/blocks/command-ui.js` 產生；驗收為 `test/ui-commands.mjs` 與瀏覽器腳本 `tools/ui-commands-browser.mjs`。下方的「代表按鈕」欄是 UI-1 之前的分群，僅供沿革。

| 群組 | 目的 | 代表按鈕 | 顯示原則 |
|---|---|---|---|
| 專案 | 檔案與範例 | 復原、存檔、開啟、分享、範例、回首頁 | 桌機在上方；手機收進「專案」選單 |
| 建構 | 放新零件 | 地錨、桿件、滑軌、齒輪、動力來源 | 永遠容易找到；手機用底部抽屜 |
| 編輯 | 編選取物 | 長度、齒數、行程、角色、疊層、刪除 | 只有選取後出現；手機用底部 sheet |
| 模擬/視圖 | 看動作與切視角 | 播放、角度、置中、孔、鎖、2D/3D、軌跡 | 播放永遠可見，其餘可收納 |
| 診斷/教學 | 告訴使用者為什麼 | DOF、死點、嚙合警告、任務卡 | 不搶操作；以狀態列/提示卡出現 |

危險操作規則：

- `清空`、`刪除` 不和主要建構按鈕同群。
- 手機上危險操作要在 sheet 內，避免誤觸。
- `刪除選取` 跟著選取面板走；`清空全部` 放專案選單。

## 4. 版面模式

### 4.1 桌機：三區工作台

適用：寬度 `>= 1100px`。

```text
┌──────────────────────────────────────────────┐
│ App Bar: 專案 / 範例 / 分享 / 狀態             │
├──────────┬───────────────────────┬───────────┤
│ 建構盤   │ 2D/3D 工作畫布          │ 編輯檢查器 │
│ 左側欄   │ 底部浮動播放列          │ 右側欄     │
└──────────┴───────────────────────┴───────────┘
```

建議尺寸：

- 左側建構盤：`176-220px`，分段顯示「基礎」「傳動」「動力」。
- 右側檢查器：`300-360px`，顯示目前選取物的所有可編輯屬性。
- 畫布：吃剩餘空間，播放列浮在畫布底部中央。
- App Bar 高度：`48-56px`，只放專案級操作與整體狀態。

桌機上的按鈕呈現：

- 建構盤用「圖示 + 名稱 + 一行副標」。
- 右側檢查器用表單，不用散落浮窗。
- 底部播放列只保留播放、角度、置中、孔/鎖、3D。

### 4.2 平板：兩區 + 可收合面板

適用：`700px <= 寬度 < 1100px`。

```text
┌──────────────────────────┐
│ Compact App Bar           │
├────────┬─────────────────┤
│ 建構欄 │ 工作畫布          │
└────────┴──────┬──────────┘
                │ bottom inspector sheet
```

設計原則：

- 建構盤可在左側窄欄與底部抽屜之間切換。
- 編輯檢查器用底部 sheet，高度約 `36-52vh`，可收合。
- App Bar 不顯示所有專案按鈕；低頻操作進 overflow。
- 觸控目標至少 `44px`，常用建構按鈕至少 `52px`。

### 4.3 手機：畫布優先 + 底部工作列

適用：`< 700px` 或 coarse pointer。

```text
┌────────────────────┐
│ Top Bar: 返回/範例/更多 │
├────────────────────┤
│                    │
│      工作畫布        │
│                    │
├────────────────────┤
│ Play Strip          │
├────────────────────┤
│ Tabs: 建構 / 編輯 / 視圖 / 專案 │
└────────────────────┘
```

手機規則：

- 第一目標是保留畫布高度，避免零件盤長期吃掉太多空間。
- 底部固定四個 tab：`建構`、`編輯`、`視圖`、`專案`。
- 點 tab 後開 bottom sheet；未開 sheet 時只留薄底欄。
- `播放` 可以獨立成一條小浮列，永遠可用。
- 選取物件後自動切到 `編輯` sheet；sheet 可下滑關閉。
- 3D 是「檢視模式」，開啟後暫停 2D 編輯，避免手勢衝突。
- 沒有 hover 依賴；所有說明都要能以 title 以外的方式被看見。

手機安全區：

- 所有底部 UI 都要加 `env(safe-area-inset-bottom)`。
- sheet 展開時不可遮住播放列與系統手勢區。
- 橫向手機高度不足時，建構/編輯 sheet 只顯示兩行快捷項，其餘進「更多」。

## 5. 建構盤分類

未來零件會增加，所以零件盤不能只是一排卡片。建議分為三段：

### 基礎

- 地錨 / 固定孔
- 桿件
  - 連桿：兩個孔，固定長度
  - 三點桿：三個孔，剛性板
- 滑軌

### 傳動

- 齒輪對
- 齒條齒輪
- 皮帶輪
- 凸輪從動件

### 動力

- TT 馬達
- MG995 伺服
- 線性致動器

操作策略：

- 桌機：三段直接在左欄顯示，可用小標籤分段。
- 平板：顯示分類 tab，同一時間只顯示一段。
- 手機：底部 `建構` sheet 先顯示分類，再進入該分類的零件網格。
- 大類可再展開子類；例如先點 `桿件`，再選 `連桿` 或 `三點桿`，避免手機底部列塞太多相近按鈕。

---

## 6. 編輯檢查器分類

選取後右側欄 / bottom sheet 以物件類型切換內容，但內部順序固定：

1. **身份**：物件名稱、類型、顏色或圖示。
2. **幾何**：長度、齒數、模數、行程、座標。
3. **角色**：自由/固定/馬達/軌跡點。
4. **裝配**：疊層、馬達-機架-曲柄、固定端、翻面。
5. **操作**：複製、轉換、分離、刪除。

高頻調整用 stepper；連續數值未來再加 slider。  
手機上同一時間只展開一段，避免長面板壓住畫布。

---

## 7. 模擬與視圖列

播放列應該穩定，不跟零件盤混在一起。

永遠可見：

- 播放/暫停
- 目前角度

桌機/平板可見：

- 置中
- 孔
- 鎖
- 3D

手機收納到 `視圖`：

- 置中
- 顯示孔位
- 鎖定 8mm
- 2D/3D
- 清除軌跡 / 顯示軌跡

`孔` 與 `鎖` 是模式開關，應保留狀態顏色；`3D` 是檢視模式，開啟後應有明確返回 2D 的入口。

## 8. 斷點與尺寸規則

建議斷點：

| 名稱 | 條件 | 版面 |
|---|---|---|
| desktop | `min-width: 1100px` | 左建構欄 + 中畫布 + 右檢查器 |
| tablet | `700px-1099px` | 窄建構欄或底部抽屜 + bottom inspector |
| phone | `< 700px` 或 coarse pointer | 底部 tab + sheet |
| tiny phone | `< 380px` 或高度 `< 620px` | 文字縮短、只留圖示與必要值 |

尺寸規則：

- 觸控按鈕最小 `44x44px`。
- 主要建構按鈕手機建議 `64x56px`。
- 桌機小工具按鈕可 `32-36px`，但文字按鈕不可低於 `36px` 高。
- 所有 floating/sheet 面板最大高度要受 viewport 限制。
- 畫布可操作區不可被永久 UI 遮住超過 30% 高度。

目前實作狀態：

- `part-palette` 已先改成「基礎 / 傳動 / 動力」分類。

- 彈出選單已加上共用 `tool-menu` class，保留既有 `power-menu` 相容樣式。

### UI-P3：手機 bottom tabs / sheets

- 建立 `建構 / 編輯 / 視圖 / 專案` 四個 tab。

- 手機寬度已新增底部 `建構 / 編輯 / 視圖 / 專案` tabs。
- `建構` 會顯示既有零件盤；`編輯 / 視圖 / 專案` 先以輕量 sheet 承接常用按鈕。

### UI-P4：按鈕分類與 overflow

- 專案按鈕收進 App Bar / 專案 sheet。
- 低頻視圖按鈕進 `視圖`。

### UI-P5：診斷與教學入口

- 在畫布上方或 App Bar 顯示簡短狀態：可動 / 太鬆 / 卡住 / 缺馬達。
- 建立任務卡入口，但不做成 landing page。

## 10. 驗收

每個 UI phase 都要跑同一組黃金流程：

1. 載入每個 blocks 範例，播放 2D。
2. 切 3D 預覽，確認可旋轉/縮放，再回 2D。
3. 新建：連桿 + 地錨 + 馬達，播放。
4. 手機尺寸：新增連桿、拖曳接點、開/關 bottom sheet。
5. 平板尺寸：左欄/底部 sheet 不遮住主要操作。
6. 桌機尺寸：右側 inspector 不擋畫布。
7. 存檔、開啟、分享、復原都維持可用。

建議測試 viewport：

- `1366x768` 桌機
- `1024x768` 平板橫向
- `820x1180` 平板直向
- `390x844` 手機
- `360x640` 小手機

## 12. 新增與點選修改精簡（2026-10-29）

使用者確認以「放零件 → 接起來 → 調尺寸與固定 → 播放 → 組立製作」為操作主線。本包只調整新增入口與點選修改的提示，不重寫求解、安裝流程或作品格式；本節取代先前新增分類的呈現方式。

- 電腦左欄、手機新增分頁共用同一份指令：直接顯示連桿、板件、馬達。「其他零件」收納固定支點、三角板、折線桿、滑軌、舵機、線性致動器、液壓針筒、齒輪對、齒輪齒條與鏈輪鏈條；保留加入模組與外掛。
- 不再把「固定」當作獨立區塊，不以「會動的零件」統稱構件。一般固定操作沿用點孔 → 固定在底座／取消固定；新增獨立固定點仍可從其他零件取得。
- 保留點選即開屬性：連桿／合成件可改孔距、複製、鏡射、刪除；點孔顯示固定或馬達安裝。手機未選取時的調整頁提示直接點零件／孔，不要求先切換頁籤。材料仍在製作設定。
- 手機常用三項並列、其他零件兩欄，文字允許換行、主要按鈕至少 44px；選項獨立捲動。直式保留底部屬性面板及收合，橫式新增盤改窄左欄；桌機維持左新增、右屬性。
- 驗收：390×844、360×640、844×390 與 1366×768 檢查入口、換行及畫布可見範圍；從空白新增連桿、點孔固定、點桿改尺寸、安裝馬達、播放、取消／復原與保存重開。Node 回歸不能代替這項 HTTP 瀏覽器驗收。

## 13. 手機直式保護工作區（2026-11-01）

問題：手機直式時，下方面板、播放列、量尺／工作範圍／任務浮動卡與頂端提示一起吃掉畫布。390×844 空白畫布只剩 40%、選取零件 46%、量尺 42%；360×640 只剩 23%、28%、16%。目標：預設（沒有主動展開任何面板）時，沒被擋住的工作區至少是視窗高度的 60%。只改手機直式（`(max-width:700px) and (orientation:portrait)`、設計模式）；電腦、平板與橫式不變，1280×800 前後截圖逐像素相同。

### 13.1 下方抽屜（單一元件、三段）

- 一個抽屜取代原本分散的下方面板：**收合**＝分頁列＋一行摘要（沒選取時是這個分頁的提示；選取零件時是「名稱：主要數值」加「更多」）；**半開**＝主要欄位；**全開**＝全部內容。有看得到的抓取把手。
- 狀態轉移是純函式 `nextSheetState`（`js/blocks/mobile-workspace.js`，契約測試 `test/mobile-workspace.mjs`）：點畫布空白、開始拖曳、平移、雙指縮放→收合；點摘要列或往上拉→往上一段；往下拉→往下一段；點下方分頁→收合時開半開，已展開則維持。**選取零件不展開**：收合時只更新精簡列，點它或上拉才進入編輯。
- 抽屜是疊在畫布上的覆蓋層，畫布尺寸不因它改變；狀態寫在 `body[data-sheet]`，高度寫在 CSS 變數 `--sheet-bar-h`、`--sheet-body-h`、`--sheet-h`，改變時送出 `sheetchange`。
- 實作（`js/blocks/work-sheet.js`，啟動後才動態載入）把既有的調整面板、量尺卡（`#dimPanel`）、工作範圍／夾持卡、任務卡原樣搬進抽屜，離開手機直式時再搬回原位（以註解標記還原位置），各面板的邏輯與 id 不變，所以桌面與橫式沒有差異。

### 13.2 頂端訊息列

- 設計分頁下方一條訊息列（`#messageLane`，`pointer-events:none`，點擊穿透到下面的桿件）。資訊、成功、已載入、警告幾秒後自動消失；錯誤改進狀態點（併入播放列，點開看詳情）；只有需要使用者確認的才用對話框（`window.alert` 已全部改成訊息）。
- `messagePlacement`（純函式）決定訊息放在哪一條：橫式與桌面保持原位，手機直式一律走訊息列，並避開頂端分頁與抽屜。

### 13.3 浮動卡進抽屜、置中只算看得到的範圍

- 量尺、工作範圍／夾持、任務卡不再浮在畫布上，改成抽屜中的一列；畫布只留畫出來的尺寸線。
- `fitView`、載入範例與課程的置中改用 `visibleWorkRect`：視窗扣掉頂端列、抽屜（收合高度）、播放列後的矩形，`View.fit(bounds, area)` 與 `resetView(area)` 接受這個矩形；機構因此一定落在看得到的區域，不被抽屜或播放列蓋住。
- 狀態點併入播放列（小圓點＋短字）。

### 13.4 啟動大小

### 14.3 3D 視角快捷、分離滑桿、整體尺寸、建議與回饋、版本字（2026-11-03，2026.11.3.2）

同樣學自電路板外殼生成器：3D 畫面有「頂 前 右 立體」快捷與「分離」滑桿，並顯示整體尺寸。設計預覽（toggle3D）與組立台共用同一個 `#view3d`，所以只做一份。

- **視角快捷**（`js/blocks3d/view-presets.js`，純函式）：`VIEW_PRESETS`＝頂、前、右、立體、置中；`presetCameraPose(id,{center,radius,viewUp})` 回傳 position／target／up。viewUp `y`（學生畫的 xy 平面）前視從 +z 看；viewUp `z` 前視從 −y 看；四個視角距離一致，切換不忽大忽小。viewer 的 `setViewPreset(id,{instant})` 先算出「該方向＋框住整個機構」的終點再做約 0.38 秒的平順移動（減少動態偏好或 `instant` 直接到位；使用者一碰畫面就中止）；「置中」＝原本的全部顯示＋框住，保留目前方向。頂視不改 `camera.up`（OrbitControls 在建構時就記住上方向），而是把鏡頭略往前偏 1%，避開正上方的奇異點。
- **分離**（`js/blocks3d/explode.js`，純函式）：`explodeOffsets(items,amount,{gap})` 以「中間層」為準，沿各項目的法向（預設 [0,0,1]）把各層拉開；`amount` 夾在 0–1，全開時相鄰層多拉開 2×gap（至少 1×gap）。viewer 的 `setExplode(amount)` 在每個零件外多包一層 `wrap`，只動 `wrap.position`，姿態更新改的是零件本身的矩陣，所以播放中兩者不互相覆蓋；每次姿態更新後與每次重建後都會重新套用。層數取自場景模型的 z／`plateGap`；主平面沿世界 z，直角安裝的子模組在自己的子 Group 內沿本地 z（＝該平面法向），各平面各自以中間層為準。針筒外形、接口標記不參與分離。
- **整體尺寸**：`getExtents()` 回傳所有零件的世界外框 `{min,max}`（mm，不含分離位移）；`formatExtents` 轉成「整體 W × H × D mm」（沒有厚度只寫兩個數；viewUp `z` 時高＝z 軸）。顯示在視角列下方，重建、點視角時與每秒更新一次（播放時跟著姿態變）。
- **模型已更新**：viewer 只在「完整重建」（不是播放時的姿態更新）觸發 `onRebuilt`；3D 剛開（0.9 秒內）或第一次建置不顯示，其餘顯示約 1.5 秒的淡出小膠囊（右上，不蓋視角列與播放列）。
- **版面**：視角列在 `#view3d` 左上（設計模式讓出設計分頁列），寬 206 px；按鈕高 32 px，手機（≤700 px 或觸控）38 px；滑桿沿用數值欄的握把樣式（深色底）。原本置中的「3D 預覽」提示移到播放列上方，避免和視角列重疊。標記寫在 `blocks.html`，接線在懶載入的 `js/blocks3d/view-tools-ui.js`（`createViewer` 偵測容器裡有 `.view-presets` 才載入），所以 `view-presets.js`、`explode.js`、`view-tools-ui.js` 都不在啟動閉包內。
- **說明 → 建議與回饋**：`ui-commands.js` 新增 `href` 型指令（`{id:'feedback',group:'help',href:'https://github.com/cieoco/cadcam/issues/new'}`）；`command-ui.js` 對有 `href` 的指令產生 `<a target="_blank" rel="noopener">`，電腦選單與手機共用同一支 `button()`；派送器略過沒有 `run` 的指令。
- **版本小字**：電腦版標題旁顯示 `v{APP_VERSION}`（11 px 灰字，`#appVersionLabel`），點一下等於按 `#versionBtn` 開版本視窗；≤700 px 隱藏（手機仍可從 說明 → 版本 開）。
- **啟動大小**：1,975,256 → 1,975,695 bytes（+439：command-ui +110、ui-commands +195、version-info +134），`test/startup-size.mjs` 上限 1,977,000 未動。
