### W3：自建接口、接合與保存

實測發現同一轉軸同時屬於活動臂和末端立桿，原本自動取第一個零件會讓輸出端跟錯方向。新增可用 body 清單與選擇：共用點需先選「輸出端跟隨哪個零件」，單一候選維持直接操作；無效／跨模組 body 拒絕。純 API 未傳選擇時維持舊相容行為。

以自建模組 4 的 P33b 選擇 Link35，而不是 Link33，設為輸出 1、存到我的模組庫；自建模組 5 安裝到此輸出。實測一次復原恢復未安裝、重接、拆下、再接及重新整理後仍顯示已安裝。從設計清單加入模組 5 時，其宿主一併加入組立；設定模組 4 為底座。組立可分別切換 M4 升降與 M5 夾爪試播（原作品已有 M1/M2，故不是重新編為 M1/M2）。

既有設計面板的「安裝到」是直接套用、可復原，不新增假預覽；組立的候選預覽取消／確認由 W1/W4 路徑覆蓋。自建接口只有定位／方向，沒有自動變成已核對的雙孔五金接口。

實際從 UI 下載 `FTC自建接合驗收.json`，本機保存為 `w3-scratch-mounted.json`。離線檢查直接讀該下載檔：正規化保留 output body=Link35 與 Mod2→Mod1 接合；以既有 assembly 求解器，升降 0–60° 每 5° × 夾爪 0–15° 每 5°，52 個組合姿態皆可解，末端立桿方向保持 90°。腳本 `check-scratch.mjs` 與輸出僅在本機證據目錄。這是有限取樣幾何證據，不是全行程碰撞或承載驗證。

組立仍報底板／連桿的目前姿態干涉與未檢查項目；未把這個人工自建測試件發布成可製作範例。截圖 `w3-scratch-assembly.png`。

### 真正空白建立

另一獨立 origin 從 0 件開始：三次兩點連桿繪製，再以「其他桿件 → 折線桿」三點繪製取物臂；共用機架與連桿端點，設定兩個固定點。在共用軸放 MG995 時，既有提示要求選擇被驅動桿，選曲柄而非機架，終角縮為 60°後試播。沿「存成模組 → 存到我的模組庫」完成重用，並下載 `擺臂骨架自建驗收.json`。

這是同類原理的操作測試骨架，不是重建原範例施工尺寸。實際下載檔為 4 件、1 模組，機架／中間桿 120 mm、曲柄 64 mm、折線桿三孔距約 64.119／88／144 mm；直接讀下載檔用既有組立求解器作 0–60°、每 0.5°共 121 姿態取樣，全部可解。未將此測試件加入公開庫；本次沒有發現必須新增專用繪製工具的缺口。
