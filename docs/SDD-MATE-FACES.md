# SDD — 接合面：設計時先決定「從哪裡接」，手機精靈一次接一個

> 日期：2026-10-07。狀態：**使用者已確認 §9（2026-10-07），M0 盤點完成，§3／§4 已依盤點結果修訂；M1～M5 完成；下一包 M6**。
> 上位文件：[SDD-ASSEMBLY-BENCH.md](SDD-ASSEMBLY-BENCH.md)（組立台、接口、直角安裝、角碼）、[SDD-ASSEMBLY-WIZARD.md](SDD-ASSEMBLY-WIZARD.md)（六面體精靈 W0–W4）。施工記錄寫在 [FTC-LOOP.md](FTC-LOOP.md)。

## 0. 一句話

每個機構在**設計時**就標好「我從哪裡裝上去」（安裝面）和「別人可以裝在我哪裡」（承接面）；**組立時**手機精靈只問「這個要接到誰的哪個面」，接上就是**做得出來**的接合（角碼／對鎖、孔位、五金、干涉檢查），重複幾次組成整台。

## 1. 現況與缺口（2026-10-07 版本 `6480970`，手機 390×844 實測）

| 項目 | 現況 | 缺口 |
| --- | --- | --- |
| 接法 | 三套並存：同平面對鎖（`mount.to.output`）、直角（`mount.orient`，有角碼／孔位／五金／干涉）、六面體（`mount.face` v1） | 六面體接完是「轉接件待設計、跨面干涉未驗證」，做不出來；三套互不相通 |
| 選面 | 精靈裡只畫兩片孤立的板，面名相對板子 | 看不出爪朝哪、臂往哪；3 mm 板邊在手機上點不到 |
| 入口 | 選卡片 → 往下捲 → 「六面體精靈」，與十幾個工程接口按鈕同頁 | 手機預設不是精靈；內部零件名（`LiftCrank_1・上`）外露 |
| 精靈畫面 | iframe 對話框，四步 | 標題區佔約 1/5 螢幕；第 1 步常是空轉；對齊步驟的箭頭被尺寸按鈕蓋住；預設間距 5 mm |
| 多構件 | 底層支援巢狀安裝、自動編號、組合積木 | 手機上看不出誰接在誰上面；同一面接多個沒有排位與檢查 |

測試基準（`node --no-experimental-webstorage`）：122 支通過；`assembly-schema`、`solve-health`、`trace-fallback` 三支為本案開工前既有失敗，不在本案範圍，但不得新增失敗。`test_blocks_schema.mjs` 94 passed。

## 2. 設計原則

1. **只有一套接法。** 精靈是現有可製作接法（直角角碼、立在面上、同平面對鎖）的手機操作方式，不另立契約。
2. **接合面跟著機構走。** 存在模組裡，進模組庫、匯出、組合積木都帶著。
3. **不設門檻。** 沒標也能組：內建模組預先標好；自己畫的由系統建議，設計時可改。
4. **一次接一個、樹狀。** 每個機構只有一個上家；整台有一個底座。
5. **每一步都看得到真實機構。** 在組立台的真實 3D 裡亮起可接的面，不另開示意畫面。
6. **做不出來就講明。** 配不出可製作接合的組合不提供，或清楚標成「僅擺放」（見 §9 Q2）。

## 3. 資料模型：`module.mates`（依 M0 修訂）

```jsonc
"mates": {
  "attach":  { "normalDeg": 90 },
  "receive": [
    { "id": "r1", "name": "工具架下緣", "ref": { "kind": "bar", "id": "ToolBrace_1", "side": -1 } },
    { "id": "r2", "name": "滑台",       "ref": { "kind": "bolt", "output": "carriage" } },
    { "id": "r3", "name": "底板右緣",   "ref": { "kind": "frame", "normalDeg": 0, "order": 0 } }
  ]
}
```

- `attach`（安裝方向，至多一個）：模組自己座標裡「朝向宿主那一側」的外法線角度，取 90° 的倍數。**不是**底板的某一條邊——M0 發現底板的形狀與邊數會隨接法改變（直角安裝時轉接孔會撐出外框、基準點的孔會拿掉），邊編號不穩定；方向才穩定。
- `receive`（承接面，可多個，上限 8）：對現有自動接口的**穩定參照**，不存座標，零件改尺寸自動跟著走。
  - `bar`：桿 id＋哪一側；`triangle`：板 id＋第幾條邊；`bolt`：輸出端 id。
  - `frame`：外法線角度＋同方向的第幾條（沿邊方向排序）。不用 `edge:frame:<k>`，因為 k 會隨安裝狀態與其他模組改變。
- 參照指不到東西（零件被刪）時該筆標為失效並提示，不靜默丟棄。
- 舊檔沒有 `mates`：讀檔不變、不補欄位；需要時由 `suggestMates()` 即時建議，使用者採用或修改才寫入。
- 內建模組在範本裡預先標好；範本／組合積木實體化時參照跟著新的零件 id。
- `name` 不顯示內部零件 id。

**建議規則**：安裝方向＝「基準點→機構重心」的反方向取最近的 90°；承接面＝每個輸出端桿的兩條長邊，以及有 2 個以上對鎖孔的輸出端。

**`ownPorts()`**：模組「自己」的接口。M0 發現目前所有未安裝的模組共用一塊合併的世界機架板（三個模組並排時，每個模組都回報同一條 429 mm 的邊）；`ownPorts` 把其他未安裝模組排除後再算，結果只和模組自己有關。

## 4. 配對表：承接面 → 哪一種接合（依 M0 修訂）

| 承接面（宿主） | 接法（精靈微調步驟可切換） | 沿用 | 產出 | M0 實測 |
| --- | --- | --- | --- | --- |
| 板邊（桿、三角板、機架、底板） | 壓在邊上（預設） | `mount.orient` edge `host` | 角碼×2、兩邊各 2 孔、M3×6×4 | 通過 |
| 同上 | 立在面上・上面／下面 | `mount.orient` edge `child` | 同上 | 通過 |
| 有 2 個以上對鎖孔的輸出端 | 平貼・對鎖 | `mount.to.output` | 對鎖關節、M3＋防鬆螺帽 | 齒條滑台通過 |
| 只有 1 個孔的輸出端 | 不提供 | — | — | 四連桿工具架接得上但沒有孔與五金 |

- 「立在面上」的位置是貼齊宿主那條邊的板面，不是板面上任意位置；所以承接面一律以「邊」標記，上面／下面是接法選項。
- 子模組的安裝方向 → 壓在邊上時決定接合線方向（`childAxisDeg`），立在面上時選外法線最接近的那條底板邊（`childEdge`）。壓在邊上的接合線通過基準點（沿用已驗收的幾何，M3 決定不擴充 `orient`）；`childAxisDeg`＝安裝方向＋180°。
- 新增純函式 `mateConnect(...)`：依上表呼叫現有 `connect()`／`benchAdjust()`，回傳相同的 `{ ok, comps, modules, reason }`。
- 微調沿用 `benchAdjust`：沿邊滑動（5 mm）、換邊、掉頭、上面／下面。接合面貼合，不提供自由偏移與任意間距。
- `mount.face` v1：資料與讀檔保留、畫面照舊顯示並標「僅擺放」；新精靈不再產生它。

## 5. 使用者流程

### 5.1 設計模式（每個設計分頁）

- 工具列多一顆「接合面」。按下後，可標的板邊與板面在 2D 亮起（粗線帶，手機命中範圍 ≥ 44 px）。
- 點一下 → 小選單：「安裝面（我裝到別人身上）」「承接面（別人裝到我身上）」「取消標記」，可改名。
- 已標的面常駐顯示：安裝面綠色帶、承接面藍色帶，旁邊小字名稱。
- 沒標安裝面的分頁顯示一行建議：「建議以底板後緣安裝　[採用] [自己選]」。

### 5.2 組立模式（手機精靈，取代目前預設面板）

上方卡片列改為**結構清單**（樹狀縮排）：

```
● 底座（底座）
  └ 四連桿升降臂 → 底座・上緣
      └ 齒輪夾爪 → 工具架下緣
○ 未安裝：第二支夾爪
```

1. **選要裝的機構**：點「未安裝」裡的一張卡。只有一個未安裝時自動選中。
2. **選承接面**：真實 3D 裡，所有已在樹上的機構的承接面亮起並標名字；下方同時列出同名大卡片（3D 點不到時用）。配不出接合的面不亮。
3. **微調與確認**：立刻以預設位置預覽（半透明）。大按鈕：◀ ▶ 沿邊、換邊、掉頭、上面／下面（只顯示這個接法用得到的）。下方即時顯示「目前姿勢沒有干涉／撞到 ×××」。按「接上」完成，一筆復原。
- 接好後點清單裡任一個：「重新調整」「拆下」。拆下中間的機構時，底下整串一起回到「未安裝」並保留彼此的接法（一筆復原）。
- 「全行程測試」每次接上後自動對**整台**跑一次，結果列在清單下方。
- 工程用的完整接口清單、六面體自由擺放收進「進階」；電腦寬度下預設仍可展開。

## 6. 多構件規則

- **底座**：第一個放進來的機構是底座（不裝在別人身上）；清單上可「設為底座」互換。M0 發現目前未安裝的模組會被合併成同一塊機架板（製作包也是），M5 要改成只有底座算機架，其他未安裝的不進製作包並提示。
- **同一承接面接多個**：每個接合沿邊佔用一段（角碼兩片 20 mm＋兩側各 2 mm）。新接的自動排到第一個空位；滑動時不可與既有佔用段重疊，重疊時按鈕停住並說明。板面對鎖比對孔位，孔心距 < 6 mm 視為衝突。
- **限制**：一個機構只有一個上家。兩端都固定（橫板、雙側板夾持）形成封閉環，本案不做；替代做法是把那片板畫進其中一個機構。組立台上明講，不讓使用者以為可以。
- **數量**：沿用模組上限 16。

## 8. 不做（本案）

- 封閉環（一個構件接兩處）、任意角度與任意間距的接合、跨面轉接件的自動設計。
- 刪除 `mount.face` 資料或工程模式程式碼（先收進進階，等精靈穩定再另案處理）。
- 力學（扭力、彎曲）；修改 svg2gcode。
- 開工前既有的三支失敗測試。

## 9. 需要使用者確認

- **Q1 精靈的終點**：改為只產生可製作的接合（§4 前三列），六面體自由擺放收進「進階・僅擺放」。建議：是。
- **Q2 配不出來的組合**（板邊對板邊等）：(a) 不提供；(b) 提供但標「僅擺放」。建議：(a)，畫面最乾淨。

## 10. M0 盤點結果（2026-10-07，基準 `2b3050f`）

做法：用現有 `connect()`／`benchAdjust()` 把齒輪夾爪接到四連桿升降臂與齒條升降的每一種接口，逐一看安裝紀錄、製作計畫的關節與孔、五金表、當下干涉。

1. **直角・壓在邊上**（桿邊、機架邊）：全部接得上；每次都產生角碼×2、宿主與子模組底板各 2 個孔、M3×6×4。轉 90°、掉頭可用；桿邊可換邊，板與機架邊只有朝外一側（符合實物）。
2. **直角・立在面上**：全部可用，上面／下面可切換。夾爪底板只有 2 條邊可當站立邊（底板由兩個固定點形成長條）。
3. **平貼・對鎖**：齒條滑台（2 個對鎖孔）產生 2 個對鎖關節與 M3；四連桿工具架輸出端只有 1 個點，接得上但**沒有任何孔與五金**，不能當成可製作接合。
4. **邊編號不穩定**：`edge:frame:<k>` 的 k 與邊長隨「是否已安裝」「旁邊有哪些未安裝模組」改變；不能直接存成接合面。
5. **未安裝模組共用一塊機架板**：三個模組並排時三者回報同一組機架邊（最長 429 mm）。這也會進製作包，是多構件要先處理的事。
6. **底板形狀依接法而定**：已安裝模組的底板不含基準點的孔；四連桿底板在沒有轉接孔時只剩 1 個點、算不出外框。所以子模組端不適合用「底板的某條邊」當設計時的標記，改用方向。
7. **預設位置的干涉**：夾爪壓在工具架下緣的預設位置沒有干涉；換邊、掉頭、立在面上的部分組合會撞到連桿（真實重疊），精靈的即時干涉提示必須在微調步驟顯示。
8. 角碼換邊修正（長短腳在轉角相接）已以 `2b3050f` 提交，`bracket-holes` 46/46。
