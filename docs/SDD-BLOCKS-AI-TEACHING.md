# SDD — Blocks 範例、共同操作與 AI／教學整合

日期：2026-10-10（Asia/Taipei）  
狀態：方向與分階段規格；本次只更新代理指引及文件，不代表 API、MCP、夾爪或加工包已完成。

## 1. 目標與範圍

讓零基礎學生與設計者從 FTC 的實際用途出發，用可修改的機構作品完成「理解 → 設計 → 幾何驗證 → 組立／輸出 → 實作回饋」。人工操作、教學與 AI 共用同一份作品與規則。以板材輪廓、孔、槽及角碼／轉軸組裝為主，使用必要的現成伺服、軸承、滑軌等零件。

以範例發現框架缺口，不先做通用 CAD、任意自然語言機械合成、接觸力學或 MCP 伺服器。未經來源核對的概念圖片不能作為尺寸或傳動設計的證據。

本文件承接 [FTC 模組原則](SDD-FTC-MODULES.md)，不替代 [框架穩定化 SDD](SDD-FRAMEWORK-STABILIZATION-2026-10-09.md) 的幾何、候選、組立與相容契約。穩定化完成證據與限制以 [其工作紀錄](FRAMEWORK-WORKLOG-2026-10-09.md) 為準；不要因新的 AI 方向重新施工已驗證部分。

## 3. 目標架構（逐案實現）

```text
人工 UI／教學入口                  AI 接頭（後續）
          └──── 共同操作入口 ─────────┘
                 │
        Blocks 作品／獨立候選
                 │
       正規化 → 編譯 → 運動驗證
                 │
      確認／復原／保存／預覽／輸出
```

此圖是目標分工，不表示整個共同入口已存在。先盤點案例涉及的現有回呼，再抽出最小必要純邏輯；不新增第二套狀態、求解數學或 UI。

### 共同操作的契約要求

- 操作對象使用作品內穩定 ID 與明確單位（長度 mm、角度 deg），不靠按鈕文字、畫面像素或自然語言猜接點。
- 讀取／驗證不修改來源。生成與修改先作用於獨立候選；無效結果保留診斷與草稿，不直接覆蓋正式作品。
- 確認沿用既有一筆復原、重算與保存流程。取消無副作用；過期候選不能覆蓋較新的作品。
- 診斷供人工與 AI 共讀：嚴重度、穩定問題代碼、零件／接點 ID、觀測值／預期值及修正提示。這是待定契約，實作前對齊現有結果，不假稱已實現。
- 區分正規化修補與原始輸入問題；不能默默把錯誤 AI 輸入修成另一個設計後宣稱原始作品通過。
- 第一版只暴露已驗證案例需要的讀取、建立與尺寸修改，不開放任意 JS 執行、任意 state 寫入或未列入支援範圍的操作。
- 外部模型連線、資料傳送、憑證與服務部署是後續獨立範圍；不得把 API 金鑰放入公開靜態頁或為此提前加入後端。

## 4. 範例如何驅動開發

第一個新驗證案例為 **單伺服夾爪**。開始時先畫清楚固定件、活動件、驅動軸、連接關係及開合兩姿態，明確選定單側活動或連桿同步結構；「單伺服」不等於「平行夾爪」。本文件未指定可加工尺寸、伺服型號或板厚。

候選後續包括翻斗、單軸臂、平行升降臂、平行夾爪、滾輪收集器、直線滑台、虛擬四連桿與擺動伸縮臂。這是方向清單，不是同時開工的功能承諾；下一例由前一例結果與使用者優先順序決定。

每個案例只需維護一份精簡案例紀錄，包含：

1. 實際用途、原始來源與日期；哪些結構是板材改製推論。
2. 組裝圖、兩姿態／運動圖、板件編號；圖與作品一致，不能只靠渲染外觀。
3. snapshot／範本入口、可修改參數及有效範圍；初期沿用既有欄位，不為教材強改 schema。
4. 有效與無效 fixture、測試指令與結果；版本、未驗證能力與下一步。
5. 板厚／刀具／外購件／角碼／軸／墊件及組裝假設，欠缺者標待確認。
6. 一個教學任務：「學什麼 → 修改一個變數 → 比較／反思 → 達成目標」。夾持、摩擦與承載效果安排實物驗證，不由動畫推定。

## 6. 驗收與完成程度

對每個案例記「通過／失敗／未測／不適用及理由」，不能只勾一個總完成：

- **資料：** 正規化、ID／參照、snapshot 往返；不修改使用者原始附件。
- **運動：** 在宣告的角度區間取樣驗證剛性孔距與閉環；保留無解／邊界負例，不以僅 0° 成功代表整段成功。
- **操作：** 人工與共同入口得到等價作品；候選取消、一次確認／復原、存檔重開、改尺寸後更新。
- **呈現：** 2D／3D／輸出使用同一尺寸及相同組立語意。UI 變更在 HTTP 實際驗收；手機視窗不能標成實機測試。
- **加工：** 在明確材料、刀具、五金條件下核對輪廓、孔位、安裝與輸出；沒有這些條件僅標概念或幾何驗證。
- **實物：** 試切、裝配、干涉、夾持／承載與可靠性另記；不由 Node 或瀏覽器測試代替。

常用現有起點：`node test_blocks_schema.mjs`、案例相關 `test/*.mjs`、`test/_harness.mjs`；實際完整 runner 與版本載入檢查依現行框架發布流程，不在此複製會過期的測試支數。
