# SDD — Blocks 範例、共同操作與 AI／教學整合

日期：2026-10-10（Asia/Taipei）  
狀態：方向與分階段規格；本次只更新代理指引及文件，不代表 API、MCP、夾爪或加工包已完成。

## 1. 目標與範圍

作品／設計／組立的操作語意見 [共同操作契約](SDD-WORKSPACE-OPERATIONS.md)。新增功能先核對資料、姿態、作用範圍、提交、驗證及保存六個邊界。

讓零基礎學生與設計者從 FTC 的實際用途出發，用可修改的機構作品完成「理解 → 設計 → 幾何驗證 → 組立／輸出 → 實作回饋」。人工操作、教學與 AI 共用同一份作品與規則。以板材輪廓、孔、槽及角碼／轉軸組裝為主，使用必要的現成伺服、軸承、滑軌等零件。

以範例發現框架缺口，不先做通用 CAD、任意自然語言機械合成、接觸力學或 MCP 伺服器。未經來源核對的概念圖片不能作為尺寸或傳動設計的證據。

本文件承接 [FTC 模組原則](SDD-FTC-MODULES.md)，不替代 [框架穩定化 SDD](SDD-FRAMEWORK-STABILIZATION-2026-10-09.md) 的幾何、候選、組立與相容契約。穩定化完成證據與限制以 [其工作紀錄](FRAMEWORK-WORKLOG-2026-10-09.md) 為準；不要因新的 AI 方向重新施工已驗證部分。

### 共同操作的契約要求

- 操作對象使用作品內穩定 ID 與明確單位（長度 mm、角度 deg），不靠按鈕文字、畫面像素或自然語言猜接點。
- 讀取／驗證不修改來源。生成與修改先作用於獨立候選；無效結果保留診斷與草稿，不直接覆蓋正式作品。
- 確認沿用既有一筆復原、重算與保存流程。取消無副作用；過期候選不能覆蓋較新的作品。
- 診斷供人工與 AI 共讀：嚴重度、穩定問題代碼、零件／接點 ID、觀測值／預期值及修正提示。這是待定契約，實作前對齊現有結果，不假稱已實現。
- 區分正規化修補與原始輸入問題；不能默默把錯誤 AI 輸入修成另一個設計後宣稱原始作品通過。
- 第一版只暴露已驗證案例需要的讀取、建立與尺寸修改，不開放任意 JS 執行、任意 state 寫入或未列入支援範圍的操作。
- 外部模型連線、資料傳送、憑證與服務部署是後續獨立範圍；不得把 API 金鑰放入公開靜態頁或為此提前加入後端。

## 4. 範例如何驅動開發

第一個新驗證案例為 **單伺服夾爪**。開始時先畫清楚固定件、活動件、驅動軸、連接關係及開合兩姿態，明確選定單側活動或連桿同步結構；「單伺服」不等於「平行夾爪」。本文件未指定可加工尺寸、伺服型號或板厚。

候選後續包括翻斗、單軸臂、平行升降臂、平行夾爪、滾輪收集器、直線滑台、虛擬四連桿與擺動伸縮臂。這是方向清單，不是同時開工的功能承諾；下一例由前一例結果與使用者優先順序決定。

每個案例只需維護一份精簡案例紀錄，包含：

1. 實際用途、原始來源與日期；哪些結構是板材改製推論。
2. 組裝圖、兩姿態／運動圖、板件編號；圖與作品一致，不能只靠渲染外觀。
3. snapshot／範本入口、可修改參數及有效範圍；初期沿用既有欄位，不為教材強改 schema。
4. 有效與無效 fixture、測試指令與結果；版本、未驗證能力與下一步。
5. 板厚／刀具／外購件／角碼／軸／墊件及組裝假設，欠缺者標待確認。
6. 一個教學任務：「學什麼 → 修改一個變數 → 比較／反思 → 達成目標」。夾持、摩擦與承載效果安排實物驗證，不由動畫推定。

## 6. 驗收與完成程度

對每個案例記「通過／失敗／未測／不適用及理由」，不能只勾一個總完成：

- **資料：** 正規化、ID／參照、snapshot 往返；不修改使用者原始附件。
- **運動：** 在宣告的角度區間取樣驗證剛性孔距與閉環；保留無解／邊界負例，不以僅 0° 成功代表整段成功。
- **操作：** 人工與共同入口得到等價作品；候選取消、一次確認／復原、存檔重開、改尺寸後更新。
- **呈現：** 2D／3D／輸出使用同一尺寸及相同組立語意。UI 變更在 HTTP 實際驗收；手機視窗不能標成實機測試。
- **加工：** 在明確材料、刀具、五金條件下核對輪廓、孔位、安裝與輸出；沒有這些條件僅標概念或幾何驗證。
- **實物：** 試切、裝配、干涉、夾持／承載與可靠性另記；不由 Node 或瀏覽器測試代替。

常用現有起點：`node test_blocks_schema.mjs`、案例相關 `test/*.mjs`、`test/_harness.mjs`；實際完整 runner 與版本載入檢查依現行框架發布流程，不在此複製會過期的測試支數。

## 聯集選取契約（2026-10-13）

- 手機與桌面同一流程：選板身或齒輪 → 聯集入口 → 點第二件 → 來源／結果預覽 → 確認。取消不更動作品；確認重新驗證並沿用單筆復原、保存與解除合成。
- 本輪仍限定同設計的齒輪＋三點板件；共用軸心及定位孔是現行剛性關係判定，不是通用布林聯集的必要條件。不同設計、不同運動件、已被其他板件合成或配對齒條者不可直接合成。
- 配對原因共用純函式；預覽規劃不改 snapshot，確認前作品有變化則失效。幾何檢查沿用既有外框／孔位檢查，厚度明示沿用板件。
- 預覽標出兩個來源與單片結果，44px 點選目標、視窗內捲動、底部取消／確認。尚未支援任意板件間、多片、跨平面聯集，不用自動更動接點或求解器方式冒充支援。


## DXF／SVG 匯出範圍契約（2026-10-13）

- 設計模式預設目前設計，組立模式預設目前組立；另可指定一個零件。手機可在匯出視窗選擇，不依賴切換面板後仍保留畫布選取。
- 預覽先產生實際檔案內容、名稱與數量，不觸發下載；確認對照來源修訂，再下載同一批內容。取消無副作用，來源或選取改變則要求重開。
- 組立依 assemblyWork 與 machineComps 範圍；目前設計以 compsInFocus 為輸出目標。接合家族保留為加工孔位計算上下文，但不自動加入下載清單。所選聯集來源任一件都輸出完整聯集件，不另出機架。
- 桿件、板件、齒輪、齒條及機架仍走既有 exporters；六面接合使用 faceFileExportData，液壓使用 syringeManufacturing。保留加工孔位、板材與 CNC 檢查。不更改作品、存檔格式或求解器。

### 播放前約束檢查（2026-10-13）

- 不以四構件為模擬上限。播放與 MP4 在目前模擬範圍內，共用 `motionPoseIssue` 與 `inspectMotionRange`，拒絕 solver 已回報的約束不足、無效解或漏解，不將補畫座標當成求解成功。
- 檢查目前姿態及實際播放計畫（整圈／自動往復／指定起訖範圍）；最大 2° 間隔取樣含端點，沒有有效行程不能播放。預檢不修改作品、角度、復原或存檔。
- 子組立須傳遞約束不足與失敗原因。播放逐幀再檢查；失敗時不採用該幀、停止並保留前一姿態。錄影失敗不得下載不完整成果。
- 此契約不代表已完備檢測所有約束退化、自由度、連續干涉或實體支承；液壓沿用專用驗證，既有 solver 的未覆蓋結構需另行補強。

## 連桿入口與多孔板規劃（2026-10-13）

本輪已實作：連桿主按鈕直接進入兩點繪製，獨立 44px 箭頭展開三角板／折線桿；不記憶特殊類型。沿用既有繪製、吸附、取消及復原。板件入口說明改為「前三點主孔，再加外形」。

多孔板以下為待實作規劃，不代表現有能力：

1. **先外形、再放孔**：選板件，建立封閉外形；切到「加孔」，點選位置並可輸入座標、孔徑。外形點不自動變成孔。先做單孔，等距孔列留待實際案例需要再加入。
2. **手機完成流程**：逐點預覽，提供「退一步／完成／取消」固定按鈕，不要求右鍵或精準點回起點。放孔時顯示放大選取區，雙指仍用於移動縮放。
3. **區別孔的用途**：第一階段只擴充加工孔，隨板件剛性移動，不增加運動自由度。現有前三個機構接點仍沿用既有規則；第四個以上孔要連接其他桿件，須先擴充並驗證編譯／求解，未支援時明確拒絕，不默默忽略。
4. **共用作品資料**：盤點既有 vertices、孔位及輸出資料後再定最小擴充契約，保留舊存檔。GUI 與未來 AI 共用建立、預覽、確認及診斷入口，不另建求解器。
5. **驗收案例**：同一片板含機構接點與額外加工孔，移動時孔距保持；測試板外孔、重複孔、孔超出邊界、自交外形與不支援接點。驗證取消無變更、確認單筆復原、保存重開、2D／3D 及 DXF 孔位一致。以一個實際支架案例貫通後，再考慮孔列及更多運動接點。

現有 startDrawPolygon 的第四點起為局部外形點，預設不鑽孔、不參與求解；不能只改名稱就宣稱已支援多孔板。


## 教材同步與指定成果試點（2026-10-13）

- 第一輪僅 80 mm 推送器：設計模式「匯出」／手機「專案」提供檢查入口，純函式 checkSliderLesson 只讀目前設計 comps／params，重開作品也可重新檢查，不保存過時的通過標記。
- 限單 TT 曲柄、單浮桿、單滑塊，核對接點 ID 後沿用 compileTopology、solveTopology 與 inspectMotionRange；整圈每 1° 取樣並沿滑軌方向投影量測。80 ±0.2 mm 為本課的取樣容許差，不是加工公差。
- 達成／尚未達成／無法判定分開；達成可接既有 MP4 匯出，修改後重新檢查。額外桿件不判定為物理上不可能，僅超出本課範圍。未驗證連續極值、碰撞、承載與實物。
- tools/capture-slider-lesson.mjs 在 CUA 瀏覽器環境檢查半成品的新增入口／無法判定，再重跑完整範例的 60 → 80 mm 檢查操作，依 APP_VERSION 產生候選圖與 manifest；按鈕／選取／成果不符則停止。這是檢查入口的示範，不代替半成品補接教學。
- 截圖需人工核對後才複製至 media/tutorials/keyshots；不自動覆蓋教材，不每次版本無差別重錄影片。其餘六課尚未自動化。
- 重跑方式：先啟動 HTTP server，於 cua_repl 讀取瀏覽器操作文件，建立獨立本機測試分頁與對應 browser／DOM tab；匯入此腳本並呼叫 captureSliderLesson({ ui, tab, browser, baseURL, outputRoot })。ui 是 cua.createBrowserTab 的回傳，tab 為 browser.tabs.get(ui.id)，outputRoot 建議 output/lesson-candidates；使用測試用 origin，因載入範例會替換該 origin 的自動保存。輸出於版本／slider，需主機支援 AX stepper 設值；不支援時明確失敗，不跳過驗收。
