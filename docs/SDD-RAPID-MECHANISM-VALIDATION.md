# SDD — 直覺操作與快速機構驗證

日期：2026-11-05（Asia/Taipei）  
狀態：規格已建立；P0 文件完成，P1–P5 尚未實作／驗收。  
盤點基準：`4fd6b45`／`2026.11.3.3`。本次交付是修正規格，沒有變更產品介面或宣稱下列功能已完成。

## 1. 要解決的問題

產品的首要工作是讓使用者快速回答：「這個機構能不能產生我想要的動作？改哪個位置會更接近目標？」

主流程定為：**畫出零件與連接 → 指定哪裡不動 → 指定從哪裡驅動 → 選輸出與目標 → 試動 → 修改比較 → 需要時補實體安裝。**

使用者不必事先知道完整設計。每輪只需提出一個問題、試一個改動、保留結果；得到新觀察後可以修訂需求。SDD 記錄當輪決定、限制與驗收，不要求一次預知整個產品。

目前主要摩擦：

- 初次試動太早遇到馬達型號、管夾、套筒等實體選擇。
- 「一起動」「可相對轉動」「沿方向滑動」分散於孔位合併、合成、安裝等操作，使用者須猜不同入口的差異。
- 無解、缺少連接與軟體未支援容易混淆；修正方向不夠具體。
- 已有量尺與行程檢查，但缺少一致的「設定目標 → 看差距 → 比較前後」入口。
- 回歸測試可證明已覆蓋行為可靠，尚不能證明新手能快速得到答案。

## 2. 範圍與既有契約

第一輪限 **設計模式、同一平面、單一驅動**，先做針筒轉盤，再驗證四連桿及雙齒輪旋轉式夾爪。範例修改與自由建立使用同一套操作；空白建立另測，不以成功載入範例代替。

沿用 [共同操作契約](SDD-WORKSPACE-OPERATIONS.md)、[範例與教學方向](SDD-BLOCKS-AI-TEACHING.md)、[統一桿件](SDD-RIGID-MEMBERS.md)、[行程驗證](SDD-MOTION-RANGE-VALIDATION.md) 與 [支撐檢查](SDD-SUPPORT-VALIDATION.md)。既有設計／組立範圍、候選提交、復原、保存與加工檢查繼續有效。

本 SDD 規劃的新概念試動入口，在對應工作包完成後才取代該範圍的先選實體硬體流程；現有馬達／針筒安裝及舊作品仍可使用。這不是把現有必需的固定關係隱藏掉。

暫不包含任意 3D 約束、多自由度通用求解、接觸／摩擦／受力、液壓壓力與流量、馬達扭力、自動設計機構、AI／MCP 服務。教學、盒體與製作輸出保留，這輪不擴充其功能。

## 4. 使用者操作契約

### 4.1 同一個工作區，逐步補細節

- 保留「設計／組立」現有切換；不另造第三個作品模式。設計預設以試動所需的資訊為主。
- 選零件或接點時，顯示相關操作；沒有選取時顯示下一步短提示。加工規格從既有製作設定進入，老師模式與模擬模型的有效性無關。
- 初次模擬允許理想固定支點及理想驅動。畫面明示「理想固定／理想驅動」，不要求先畫螺絲，也不偷偷替使用者增加地面固定點。
- 使用者主動選「實體安裝」才補型號、固定座與配對孔。切換顯示層級不改機構資料或驗證結果。

### 4.2 選對象，再選關係

| 使用者要做的事 | 預期互動 | 必須保留的區別 |
| --- | --- | --- |
| 這裡不動 | 點孔 →「固定此點」；整片固定另顯示「固定整片」 | 一孔固定仍允許零件繞孔轉，不等於整片不能動 |
| 兩件在這裡相接 | 點來源孔 →「接到…」→ 點目標孔 → 預覽確認 | 相接可相對轉動；只在畫面重疊不算連接 |
| 兩件一起轉／一起移 | 選兩件 →「固定在一起」→ 顯示相對位置與受影響對象 → 確認 | 剛性連接不等於兩片加工輪廓「合成一片」，不因點兩孔就默默切料 |
| 沿一個方向滑動 | 選滑塊／滑軌 → 確認導引方向與行程 | 導引關係不自帶動力 |
| 從這裡轉／推拉 | 選接點與輸出件 →「旋轉驅動」或「伸縮驅動」→ 拖動輸入 | 驅動必須有明確承載基準；不能以固定活動件來掩蓋欠約束 |

第一版「固定在一起」只開放已有可驗證規劃器的組合：合成桿件、齒輪與夾指等。沿用兩孔定位需要時，在畫布標出軸心孔與定位孔；孔距不合必須讓使用者明確選擇調整。不得先做一個看似通用、實際靠補上使用者未指定的約束或改尺寸達成的按鈕。不支援的選擇顯示原因，保留草稿。

同一操作可有桌機快捷鍵與手機按鈕，但必須呼叫同一規劃／提交入口。選取有歧義時才出現候選清單；選定後同時高亮孔與所屬零件。

### 4.3 理想驅動的最小定義

- **旋轉驅動**：明確選軸心、固定基準、輸出零件；設定起訖角與往返／連續轉動。不先要求 TT、N20 或 MG995，不把播放速度標為實際產品轉速。
- **伸縮驅動**：第一輪支援「沿已指定固定方向推拉短連桿」及「兩端可轉、直接推有固定軸的輸出件」。端點、基準長度與行程必須明示；固定方向型不能自動改成可轉型。多出自由度的任意中間連桿鏈明確列未支援。
- 使用者選 A、B 後可由目前姿態建議基準距離，確認前顯示數值。修改行程時不得重新校準基準長度來維持原姿態。
- 理想伸縮器不帶筒身外徑、管夾耳距、套筒與最短實體筒長假設；這是幾何模型。現有實體針筒保持原本 14 mm 單耳偏置及已保存規格，不自動轉成理想模型。
- 使用既有編譯／求解核心；適配層可以建立暫態求解約束，但只表示使用者明確設定的關係，不得補多餘約束。暫態求解構件不可洩漏到零件清單、保存或加工輸出。

### 4.4 直接修改與手機操作

- 點尺寸標籤即可改孔距，拖位置把手只改位置／姿態；兩者不能混用。已受約束的點說明受誰限制，不默默斷開連接。
- 拖曳中預覽，放開提交一次；Escape、取消、指標中斷回到原狀。數字輸入沿用共用元件，未修改的原始精度保留。
- 手機單指點選／拖把手、雙指平移縮放；第二指加入時取消未提交編輯並接續視圖手勢，不產生一次零件修改。
- 點選區至少 44 CSS px，輸入字級至少 16px；不以禁止放大文字達成緊湊布局。選項可捲動，主要確認／取消不遮住內容；平常保持工作區可見。
- 成功後直接留在畫布看結果，不重開精靈；長說明收進說明入口。

## 5. 要得到的答案：目標、結果與比較

### 5.1 第一版目標

選「檢查動作」→ 點輸出點／零件 → 選量測方式 → 輸入可選的目標值。沒有目標時仍可先量測。初期每個設計只啟用一個目標，避免先做儀表板。

| 量測 | 定義與顯示 |
| --- | --- |
| 位移行程 | 選一點及固定量測方向，沿該方向投影的最大值減最小值；不可用兩端直線距離冒充整段行程 |
| 轉角範圍 | 選剛性件上的有向基準（中心＋工作孔），以連續追蹤角度的最大值減最小值；跨 ±180° 需展開角度；疑似分支跳變時不判通過 |
| 夾爪開口 | 選兩個爪端並明示採「兩點距離」或已支援的「淨開口」；幾何、表格與畫面標註使用相同定義，不把中心距當淨距 |

目標第一版支援「至少」與「等於（含容差）」。角度用 °，長度用 mm；精確比較使用原始值，顯示四捨五入不可改變判定。完整採樣成功後才判定達標；一個起點可解不足以判定整段可行。

輸出包含：目前值、指定行程的極值／範圍、距離目標的差、輸入範圍與採樣步距。取樣角度／伸出量沿用各域驗證政策，明確涵蓋端點與反向；不偷偷放寬容差、縮短使用者要求的範圍。

### 5.2 明確區分結果

| 狀態 | 使用者看到的意思與下一步 |
| --- | --- |
| 待設定／待檢查 | 顯示缺少的固定點、接孔、驅動或目標；提供定位入口 |
| 指定範圍採樣可行 | 顯示量測結果與是否達到目標；不是加工、承載或連續干涉通過 |
| 結構尚未接好 | 由已知證據指出未連接／多餘約束的對象；沒有精確自由度分析時不編造數字 |
| 指定範圍未通過 | 停在第一個失敗樣本，標出輸入值與相關零件；提示檢查尺寸／範圍，不直接宣稱物理卡死 |
| 尚未支援／無法判定 | 指出目前不支援的組合或求解失敗，保留作品，不能當作使用者設計錯誤 |

所有路徑共用結果轉接：問題代碼、來源設計／零件／接點、輸入值、可定位動作、驗證覆蓋與未驗證項目。無來源資料時明說不能定位，不猜零件。未達成目標的有效機構可以保存；欠約束草稿也能保存，但不能標成可播放或驗證通過。

### 5.3 修改前後比較

- 「保留目前方案」建立唯一的比較基準 A；目前作品是 B。修改一個孔距或位置後，顯示兩者結果與差值，可勾選淡色基準輪廓。
- A 是目前設計的獨立只讀快照，不是另一組參與求解的零件；不複製到畫布、BOM 或加工檔。
- 兩者使用同一目標、參照、輸入範圍與採樣政策。若刪掉參照或改變驅動，標示「比較條件不同，請重新設定」，不排列成誤導的改善百分比。
- B 無法完成整段行程時仍保留 A；B 的部分結果可供定位，但不能和 A 的完整極值比較後標示達標。
- 「回到基準方案」預覽受影響內容，確認沿用一筆復原，不覆蓋其他設計。若新增外部組立引用，拒絕跨關係回復並指向原設計處理。
- 第一版基準 A 為工作階段資料，切換／重新開啟作品時清除並明示；目前 B 與目標正常保存。需要永久保留 A 時用既有另存，暫不加入多方案版本樹。

## 6. 資料、架構與相容設計

1. 繼續使用 Blocks 作品，不新增副檔名、框架、後端或第二套求解器。UI 呼叫純候選規劃、驗證與既有交易提交；`app.js` 只接線。
2. P1b 先補選配的理想驅動資料契約，P1c 再補目標契約。暫定資料名稱 `simulationDrives`、`motionGoals`，是提案名稱，實作前須在本節落實 schema；不得直接塞進 `motorType`，因目前未知型號會回退為 TT。
3. 理想驅動至少記錄：契約版本、穩定 ID、所屬設計、旋轉／伸縮種類、固定基準與輸出參照、起訖值及單位；伸縮另含固定方向／可轉模式與基準長度。不能只存畫面座標或靠零件名稱找對象；不得同時啟用兩個驅動控制同一自由度。
4. 目標至少記錄：契約版本、ID、設計、驅動 ID、量測種類、有效點／零件參照、固定量測方向或角度基準、比較方式、目標值與容差。優先重用量尺的參照格式；不得把目前不接受的角度種類直接傳給 `normalizeDimensions` 而被丟棄。
5. 純結果與快取不作為已驗證事實存入作品；讀檔後重算。尺寸、接點、驅動、目標、範圍、固定狀態或相關外形變更使結果失效；平移縮放、選取與播放游標不使固定範圍結果失效。加工資料變更須另使加工結果失效。
6. 所有非同步檢查帶作品修訂、目標及範圍識別；舊結果不得覆蓋新作品。既有同步掃描若影響拖曳，只預覽目前姿態，完整採樣在放開／按檢查後執行，超時顯示未完成並可取消，不能降規假通過。
7. 缺新欄位的舊檔維持原行為；不得自動把 TT／MG995／N20 或針筒改成理想驅動。新資料必須經 JSON、自存、分享、模組／分頁範圍與 undo 往返測試。未知版本／壞參照不可靜默變成另一個可動作品。
8. 新增持久化驅動會影響舊版閱讀器。P1b 必須測試舊版如何處理；需要防止靜默丟棄時，先定義格式版本或能力相容策略及遷移，再發布。不得先承諾只加選配欄位就對所有舊版雙向相容。
9. 建立共同操作轉接以實際案例需要為界，優先使用既有 `ui-commands`、域規劃器與驗證結果；不要為本輪預建完整指令框架。新純模組名稱與責任在各包開工時補記。

## 7. 接續實體製作

- 概念試動到實體安裝沿用同一份作品與零件參照；先產生候選，列出選定硬體、會改的關係／尺寸與尚未完成的固定，再確認。
- 馬達型號、針筒最短長度、單耳偏置等會改變幾何時，必須重新驗證原目標與行程；不能只換外觀就沿用通過徽章。
- 若選定硬體無法保留原動作，顯示差距與可返回概念方案的操作。既有實體作品轉為概念也必須明確選擇，不能因收起安裝面板而丟掉五金資料。
- 理想固定／剛性連接不自動產生已核對的安裝孔。未完成必要實體連接時禁止將整機標示為「可製作」；仍可依既有規則匯出有效零件的概念輪廓，列明範圍與缺項，不放寬原有加工阻擋。
- 2D 動作已驗證、3D 安裝已核對、加工資料已核對、實物已測分開記錄。老師模式只是顯示深度，不是驗證等級。

## 8. 三個端到端案例

所有尺寸先使用既有範例與 fixture；另存基準副本，不改寫使用者作品或直接重新定義教學成果。

| 案例 | 操作與要回答的問題 | 必測反例 |
| --- | --- | --- |
| H07 針筒轉盤（首例） | 現有實體版本先測伸出 0–20 mm 的盤角範圍，再建立明確的理想伸縮版本；選圓盤中心＋工作孔量角，保留 A，移動驅動固定位置或改偏心距得到 B，判斷轉角是否增加 | 沒有固定基準、端點太近、跨死點、刪掉輸出參照、超出所選檢查區間、B 中途無解 |
| 四連桿 | 從空白接成閉環、指定固定軸與旋轉輸入、選輸出桿；先量可達擺角，再改一根桿長比較 | 漏接閉環、誤固定活動孔、桿長無法形成指定姿態、支援外拓撲、全轉範圍中途失敗 |
| 雙齒輪旋轉式夾爪 | 指定一顆齒輪旋轉；鏡射夾指與對應輪連接；標出爪端量開口，比較一次孔距或爪端修改 | 只有重疊未連接、18／23 mm 定位孔距不合、外部引用阻止搬移、不對稱結構卻要求對稱、爪端交叉 |

H07 基準已有約 83.7° 的取樣往返範圍；使用者若設定「至少 90°」，應顯示未達標及差距，不改寫範例或縮改目標來讓它通過。理想伸縮與單耳實體針筒的數值不保證相同，必須標明模型條件。夾爪的對稱測試要逐樣本對照兩側軌跡；開口達標不等於對稱、夾牢或平行夾持。

## 10. 驗收與衡量

### 技術及操作檢查

- 資料：新舊作品讀寫、分享、自存、一次復原、跨設計隔離、壞參照／未知能力的明確回饋。
- 幾何：剛性孔距不變、指定輸入單位、雙向端點、角度跨界、量測與目標容差、鏡射對稱、欠約束與不支援負例。
- 交易：預覽與掃描不改正式作品；同值／無效提交不留多餘 undo；取消、手勢中斷及過期候選不寫入。
- 比較：A 保持獨立、B 失敗不清掉 A、條件不同不誤比較、基準不進加工輸出、還原不影響別的設計。
- UI：390×844、360×640、844×390 與桌機 1280×800；文字放大到 200% 仍可讀取／捲動；選點、拖曳、雙指取消編輯、數字輸入與鍵盤操作。手機尺寸模擬與實體觸控分開記錄，未做實機不得勾已測。
- 輸出：理想與實體模型清楚區分、既有零件輸出限制保留、確認硬體後重新量測。
- 每包執行對應既有測試與新增的行為負例；發布前按 repo 流程更新版本／載入圖、必要回歸、commit／push，再確認 Pages。文件包僅檢查內容、引用與索引，不提高產品版本或宣稱 UI 已驗收。

### 使用者成效（待實測的目標）

主要指標是 **從開始操作，到使用者能說出「改了什麼、結果如何、是否達標」的時間**，不是新增功能數。

- 範例修改試行目標：載入後 5 分鐘內完成一個變數修改、量測與前後比較，無開發者代操作。空白建立另外計時，不混在同一數字。
- P1a 至少記錄三案例各一條可重現路線與起止條件；觸控次數、選錯／回退、開精靈次數、求助次數分列。現階段沒有經實測的前後數字，不預填節省比例。
- P5 建議至少 3 位首次接觸本工具的使用者，各測一案例並記錄設備與經驗；若課堂人選不足，先標「開發者路線驗收完成，使用者驗收待做」，不以代理操作冒充新手測試。
- 基準版與新版用相同題目及資料；為減少先做一次的練習效應，使用等難變體或交錯順序，報告個別結果與中位數，不從小樣本宣稱普遍提升。
- 若時間未改善，優先修最常選錯或求助的一步；不能只降低測試難度、縮小字體或刪掉必要警告來取得較短時間。
