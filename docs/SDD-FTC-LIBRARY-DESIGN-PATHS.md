# SDD — FTC 機構庫與兩條設計路徑

日期：2026-10-15（Asia/Taipei）

狀態：開工規格；W0 定向盤點與基準檢查完成，其餘工作包依工作紀錄逐包更新。

工作紀錄：[WORK-FTC-LIBRARY-DESIGN-PATHS.md](WORK-FTC-LIBRARY-DESIGN-PATHS.md)

## 1. 本輪產品決策

建立「夠多、好改、能組合」的機構範例庫，同時改善從空白設計機構的易操作 UI。以既有平行四連桿、雙齒輪夾爪及升降夾爪組立為共同驗收案例。快速驗證是主線，教學沿用同一作品與操作。

兩條入口：

- A 範例修改：依用途找機構 → 載入範例或加入模組 → 改尺寸／動作 → 檢查 → 組合 → 保存自己的版本。
- B 空白建立：建立零件 → 接點連接 → 固定／動力 → 改尺寸／試動 → 定義安裝與工作輸出 → 組合 → 保存重用。

兩條路使用同一編輯器、Blocks snapshot 與域驗證。空白路徑必須真的以繪製、編輯與接合完成，不能把載入完整範例算作從零建立。

本輪取代先前討論中「以 80 mm 推送器六階段導覽為主線」的提案；推送器現有課程與驗證繼續保留，但不順便修改其起始尺寸或過關條件。不新增強制六階段精靈、常駐流程列或第二套教學／設計介面。

沿用 [FTC 模組原則](SDD-FTC-MODULES.md)、[共同操作契約](SDD-WORKSPACE-OPERATIONS.md)、[新增與修改操作](SDD-CREATION-FLOWS.md)、[剛性桿件](SDD-RIGID-MEMBERS.md) 與 [框架穩定化](SDD-FRAMEWORK-STABILIZATION-2026-10-09.md)。本規格不撤銷已完成契約。

## 2. 現有能力與首例基準

以 W0 基準提交 `d771177` 的程式為準。找到原始定義、出現在選單、具有可插入模板、經操作驗收是不同狀態。

| 現有項目 | 實際入口／資料 | 本輪用途與限制 |
| --- | --- | --- |
| 單一平行四連桿 | `parallel-fourbar`、`parallel-lift-workflow.js`／operations／controller | 既有等臂長與起終高度候選；不是通用多模組改尺寸器 |
| 雙齒輪夾爪 | `gear-gripper`、`gripper-workflow.js`／operations／controller | 既有物件寬度、餘量及爪形操作；不是平行夾爪，淨開口不證明夾住物件 |
| 完整升降＋夾爪 | `assembly-lift-gripper`，來源 `assemblyLessonSnapshot` | Lift1／Grip1、兩動力、既有工具架雙孔接合；重用資料，不另複製模型 |
| 分開待接的起點 | `assembly-lift-gripper-practice` | 由完整例移除 Grip1 對外接合並移開；用於接合取消／確認／復原驗收 |
| 內建插入模組 | `BUILTIN_MODULES`：`fourbar-lift`、`gear-gripper`、`rack-lift` | 沿用 `builtinTemplate`、`module-editor`／`module-ops`；與整份範例替換不同 |
| 自製模組庫 | `module-editor.js`／`module-ops.js` | 已有保存、匯入與組合模板相關能力；新增前先盤點，不另造庫 |
| 空白操作 | `tools.js`、`input.js`、各 editor、`design-guide.js` | 已有新增、選孔、尺寸、動力、復原；先實測卡點，不預設全盤重寫 |
| 後續候選 | `competition-rack-lift`、`tipping-bucket`、`lift-bucket`、`competition-roller-intake` | 已有來源，各自的動作、修改與輸出範圍須單獨核對 |
| 飛輪 | `competition-flywheel-shooter` | 定義存在，但被 `BLOCK_EXAMPLES` 排除；不得標成已公開或任意解除排除 |

特別注意：`parallel-fourbar`、`competition-fourbar-lift`、內建 `fourbar-lift`、組立中的 Lift1 並非完全相同模板。尺寸、工具架方向、馬達數與任務 marker 不可混用。組立來源的 M1 明示 MG995，GearA 的 M2 未明示同等舵機設定；既有六步序列是幾何模擬，不得把它描述為兩顆真實舵機已可控制。

## 3. 一個可交付範例必須包含什麼

資料先以文件與既有登錄對照；W1 決定最小程式 metadata，不先修改作品 schema。

| 項目 | 必要內容 |
| --- | --- |
| 身分與用途 | 穩定 example ID、中文名稱、用途家族、一句話用途；基礎機構與組合案例分清楚 |
| 起點 | 指向既有 snapshot／產生函式；內建模組 ID 若存在則明列，不存在不得顯示可插入 |
| 操弄 | 可改的物理量、單位、既有操作入口；已驗證區間與尚未驗證區間分開，不硬編一個所有尺寸皆可用的範圍 |
| 接口 | 固定基準、動力輸入、工作輸出、既有接合面或雙孔接口；「畫面疊在一起」不是已接合 |
| 動力 | 模擬使用的馬達／舵機數、轉動／定位語意；FTC 實際器材型號、扭矩與合法性未核對時明列 |
| 證據 | 概念示意、指定範圍模擬驗證、加工資料核對、實物測試分別記錄；各附來源／版本／範圍 |
| 來源 | 實際案例或廠商資料、日期、原方案與板材化改製的差別；通用原理來源不能當成本範例尺寸的證據 |

驗證結果來自當前作品；範例的基準證據不等於修改後作品自動通過。說明不重複儲存孔距、馬達數或其他可從正式資料取得的值，避免 UI 與作品分歧。

## 4. 兩條路徑的 UX 契約

### A：範例修改及組合

1. 入口按用途讓人找到「升降／夾取」，保留既有教學深連結與穩定 ID。先改善既有範例／加入模組入口，不先新增獨立大型範例網站。
2. 明確區分「載入整份範例（替換作品）」與「加入模組（保留現有作品）」。既有 URL 範例確認、分享 hash 優先與一次復原保持；直接選單是否缺少同等提示列為 W1 問題。
3. 操弄重用零件選取、畫布把手與現有尺寸欄位。平行等臂與夾爪對稱修改只使用已支援的配對，不依名稱猜任意關係。
4. 沿既有加入組立／接合預覽／確認／取消／拆下流程；範例載入、模組插入、加入組立是三種不同操作。
5. 不因「挑選」就套用草稿；來源過期與不支援結構給原因，不刪件湊成可接受結構。

### B：從空白建立

1. 空白設計維持「新增」可達；連桿兩點、板件主孔與外形、固定點、齒輪與動力沿原工具。
2. 接點命中、吸附候選及完成後關係要可辨識；視覺相交不可假稱接上。手機提供足夠點選區，與平移／縮放不衝突。
3. 能直接選零件改尺寸；孔位、外形、播放姿態與組立安裝分清楚。任務同步等臂功能不等於任意桿長編輯都會自動保持平行。
4. 固定點是理想約束，動力須辨識帶動對象與固定基準；沿現有播放前／逐幀驗證。編輯中的不完整骨架不刷常駐錯誤，明確試播時才提供可操作的問題說明。
5. 手機完成／取消不要求右鍵；取消不改作品，一次有效修改一筆復原。
6. 能將自行建立的設計用既有能力整理成模組、指定接口、加入組立。缺少人工建立接口的可達操作時列為缺口，不用直接注入 JSON 冒充完成。

兩條路都記錄操作次數、跨面板切換、誤選／重試與需口頭說明的步驟；先量基準，不預造「減少 50%」成效數字。優先移除一個真實卡點，再重跑同一路徑。

## 5. 架構與相容界限

- 正式資料沿 `comps`、`params`、`modules`、`assemblyMembers` 與既有 fabrication／stock；`S.mode`、`S.designFocus` 繼續只表達目前操作範圍，不作為兩份作品。
- 新的用途分類與來源說明若需程式資料，先用以穩定 ID 查詢的純 metadata；`getExample`／既有模板仍是唯一作品來源。不複製 snapshot、不在 core 操作 DOM。
- 不新建全域 Command Bus、統一 revision、通用參數化核心或新的存檔格式。只有具體案例重複需求才抽小共用入口。
- 舊檔、分享、復原及本機模組庫需繼續可讀。模組插入沿用 ID／參數／馬達重編與原接合規則；完整組合模板需要時先重用現有 composite 能力。
- 模擬角度不直接對應實際舵機命令；電控接口先記錄需求，實機通訊、校正與部署另立工作包。
- 已有支撐、孔位與目前姿態檢查先盤點重用，不把所有項目說成未實作；也不把局部檢查外推成全行程碰撞或承重通過。

## 6. FTC 家族擴充順序

| 批次 | 家族／候選 | 進入條件 |
| --- | --- | --- |
| 首批完善 | 平行升降＋雙齒輪夾爪；完整／待接兩起點 | A、B 兩條路與接合、修改、復原、保存有證據 |
| 第二批重用 | 齒條滑台＋夾爪、平行升降＋翻斗 | 先核對已有 rack-lift／lift-bucket，不重做；確認末端接口可重用 |
| 第三批補缺 | 單側夾爪、真正平行夾爪、單軸手腕、進料臂／滾輪 | 每次一例；明示接觸與摩擦未模擬，先找到有來源的結構 |
| 獨立能力 | 單級／多級皮帶繩索滑軌、姿態保持傳動 | 先列新約束需求；連續式各段順序不能硬做成確定動畫 |
| 後續研究 | 底盤／里程計、轉塔、射出、懸掛鎖定 | 行走、接觸、彈道、承載超出現有幾何範圍，不為增加數量假稱可驗證 |

不是按表一次開工。新例只有在已能改、能存、能組合且能力說明完整後才加入公開庫。未公開的飛輪保留排除，另查原原因及驗收條件。

## 7. LOOP 與模型分工

每包：指定輸入與一個問題 → 定向讀碼／重現 → 小範圍實作 → 定向測試 → 必要瀏覽器／整合驗收 → 記錄、提交與交接。

| 包 | 交付 | 涉及範圍 | 完成門檻 |
| --- | --- | --- | --- |
| W0 規格及基準 | 本 SDD、真實入口盤點、基準測試、A/B 操作初勘 | 文件、既有測試與獨立測試 origin | 區分已完成／待測；選出 W1 最小問題 |
| W1 找到並開始 | 首例用途、主要可調項／限制、載入與加入差異清楚 | examples／example-controller／module-editor 的必要局部、既有 HTML 入口 | 不改作品來源；桌面／手機可辨識載入與加入；取消／復原／深連結回歸 |
| W2 空白建立 | 實際從空白建立平行四連桿與夾爪，逐一修最高優先卡點 | input／tools／選取／相關 editor；每刀只一種操作 | 繪製→接點→固定／動力→改尺寸→試動，桌面／手機均有證據；不以範例代替 |
| W3 模組接合與重用 | 兩路產物都能指定接口、接上、拆下、再編輯與保存 | 既有 module／bench／assembly；有缺口才修改 | 取消零變更、確認一次復原、重開尺寸／接合一致；分別控制 M1/M2 |
| W4 第二組驗證 | 齒條＋夾爪或升降＋翻斗，確認真正共用內容 | 優先已有範例及接口 | 不複製核心流程；新增能力與特例分離 |
| W5 家族增量 | 每次一個有來源、可操弄的新結構 | 案例所需的最小域模組 | 同一品質清單、負例、輸出範圍與 UI 驗收 |

模型策略（本次使用者已授權適合模型與省 token 分工）：

- 主模型：定契約、核對資料、整合與瀏覽器驗收，保持單一正式寫入者；小文案／規格修正直接完成。
- `gpt-6-luna` medium：一包有界的唯讀盤點、來源／ID／測試清單及文件一致性檢查；傳短任務，不複製整段歷史。
- `gpt-6.1-sol` medium：後續局部 UI／純函式施工可用；交辦時主模型停止寫同一工作包，明列可寫檔、輸入契約、負例與測試。
- 跨狀態／求解問題先縮小重現；兩輪仍沒有進展才評估較強模型（如 `gpt-6-astra` high）做有界分析，不預設每包都用。
- 每包優先一名協作者；不為「有多模型」而拆微小工作。不以歷史模型名稱或虛構 token 百分比作成效；記實際模型、工作範圍、交接及重跑次數。
- 定向測試通過後才做必要整合；相同程式與輸入不反覆重跑全套。正式產品程式改動發布前依現行 runner、載入圖及 UI 契約完成所需檢查。

## 8. 驗收矩陣

| 編號 | 必須看見的結果 |
| --- | --- |
| A1 | 能找到升降、夾爪與完整組合；知道哪些是整份範例、哪些可加入現有作品 |
| A2 | 首例尺寸／動作可改、可取消、可復原；非法或不可達值指出原因與範圍，不自動丟零件 |
| A3 | 範例替換有明確範圍；插入模組保留其他設計，重複插入不衝突；分享網址優先 |
| B1 | 新空白設計以一般工具建立機構，無隱藏注入；孔相交但未連接的反例可辨識 |
| B2 | 固定／動力對象清楚；未完成時能編輯，試播問題可定位；操作結束與取消在手機可達 |
| C1 | 夾爪沿指定工具架接合、取消回原位、確認可復原；加入組立與刪除／關閉分頁不混淆 |
| C2 | 指定角度範圍內 M1 帶整組夾爪、M2 控制開合；孔距與接合關係保持，失敗不採用無效姿態 |
| C3 | JSON／分享重開、復原、拆下後重接保留尺寸及接口；來源修改使舊候選失效 |
| C4 | 同一板件 2D／3D／適用 SVG/DXF 幾何一致；下載成功與加工／實物驗證分別記錄 |
| U1 | 桌面及 390×844 瀏覽器視窗操作；面板不遮關鍵操作、無頁面橫向溢出；不稱實機手機測試 |

改動前先選適用列。W0 不宣稱完成 B1 或整個矩陣。每筆結果附版本、起始作品、操作與證據；不支援者列缺口，不用隱藏工具或放寬測試繞過。
